Secrets & credentials

Connecting to data sources, MCPs and APIs takes keys and logins. Flow manages configuration and secrets as named groups of keys and values, compatible with standard .env files and the way you already use them.

CredentialSpec — declare it Chapter 8 →

At build time: each secret's name, and how to configure or obtain it. No value ever sits in the file.

SecretStore — store it Chapter 8 →

Where the value lives on this machine: the project's .env file or Flow's encrypted vault. One API for both.

Secret manager — share it Chapter 8 →

When a team shares a secret, a manager holds it. GCP Secret Manager ships; others, such as 1Password, plug in with register_store.

One command, the whole life cycle Chapter 8 →

Data connectors

Agents are useless without data. Flow connects them to it: simple, secured and customizable.

Flow data connectors are managed by two SDK entities:

  • flow.DataDriver—how Flow connects to a provider, like the Slack driver
  • flow.DataSource—one specific source of data a driver works with, like a Slack channel or a shared Google Drive

flow.DataSource=flow.DataDriver+Config

Flow defines three types of data sources — what a source's items are, and where they land:

flow.ObjectSourceFilesGoogle DriveUnstructured data in path-driven stores. Its files land on disk and are indexed.
flow.RecordSourceRecordsJiraTable-driven data. Its issues are kept as rows, updated in place.
flow.MessageSourceMessagesSlackMessage-driven channels. Threaded into the stream inbox, and answered through the source.

flow.SourceItem

Every source yields items: an origin plus a typed payload. Where they land, and how you read them, is the family's.

Files — ObjectSourcePaths. Each file reflects onto disk at its own path (none, copy or symlink); a change is a page of paths.
Records — RecordSourceTables. Pages of rows whose columns are the record's fields; one line to a DataFrame.
Messages — MessageSourceSerial. Arrivals come one at a time in order, and each has a reply that goes back the same way.

flow.Agent

An agent is a deployable unit — a DataSpec, like everything else. It exposes interfaces and talks to the outside world: every channel it owns, and HTTP. One agent, many deployments.

A DataSpec, like everything elseValidated in memory, a folder on disk, the same save and load.
This is all you need to deploy a phone-calling agentAn agent, a phone line it owns, a deployment — every call a Conversation with its address.
Its own process, with HTTPAn agent runs here as one deployment: its own process, with its own chat endpoint.

Before you start

  1. Install

    pip install flowpad

    Python 3.11 or newer. Or install the CLI with uv tool install flowpad.

  2. Start the local app

    flow start

    The SDK, the CLI and the desktop app share it.

  3. Open an async REPL

    python -m asyncio

    Every example uses top-level await.

Names in capitals, such as KEY, FEED_URL or PHONE_NUMBER_ID, are values you supply. A green Runs in CI tag means that exact text, character for character, is executed by the named test on every change. The few blocks tagged illustrative are not run, and say why.
