# Local development

The template is local-first: the frontend and backend run with zero cloud
dependencies, and the database is a local Supabase stack (Docker). The app
degrades gracefully — pages render and the backend serves even when Supabase
is not running; only DB-backed features need it.

## Prerequisites

| Tool         | Version | Needed for                          |
|--------------|---------|-------------------------------------|
| Node.js      | ≥ 20    | frontend                            |
| npm          | any     | frontend deps                       |
| Python       | ≥ 3.11  | backend                             |
| uv (optional)| any     | faster backend venv (falls back to venv+pip) |
| Supabase CLI | ≥ 2.x   | local database (`brew install supabase/tap/supabase`) |
| Docker       | running | `supabase start`                    |

## One-time setup

From the project root, run the shipped script **as-is**:

```bash
python3 setup.py
```

It is idempotent. It:

1. verifies node / npm / python versions,
2. runs `npm install` in `frontend/`,
3. creates `backend/.venv` and installs `requirements.txt` (prefers `uv`),
4. copies `.env.example` → `frontend/.env.local` and `backend/.env` (only if
   missing — your edits are never clobbered),
5. reports whether the Supabase CLI is available and what to run next.

## Environment variables

Single source: `.env.example` at the project root (copied per-service by
`setup.py`).

| Variable                        | Local default                                       | Used by  |
|---------------------------------|------------------------------------------------------|----------|
| `NEXT_PUBLIC_SUPABASE_URL`      | `http://127.0.0.1:54321`                              | frontend |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | printed by `supabase start` — paste it in            | frontend |
| `DATABASE_URL`                  | `postgresql://postgres:postgres@127.0.0.1:54322/postgres` | frontend (Drizzle), backend |
| `BACKEND_URL`                   | `http://localhost:<be-port>` (the port you start uvicorn on) | next.config.ts rewrite |

After `supabase start` prints its summary, copy the `anon key` into
`frontend/.env.local`. `supabase status` re-prints it any time.

## Day-to-day loop

```bash
# terminal 1 — backend (auto-reload) on a picked port, never an assumed one
BE_PORT=$(flow app free-dev-port --bare)
cd backend && .venv/bin/uvicorn main:app --reload --port $BE_PORT

# terminal 2 — frontend (hot reload) — pick again once the backend is up
FE_PORT=$(flow app free-dev-port --bare)
cd frontend && npx next dev --port $FE_PORT     # not `npm run dev` (pins 3000)

# database, when you need it
supabase start    # boots Postgres + auth + storage + studio (Docker)
supabase stop     # shuts it down, data persists in the docker volume
supabase status   # URLs + keys
```

- Frontend: http://localhost:<fe-port> (the port `next dev` prints) — the
  landing page is a status board for all three services.
- Backend docs (auto-generated by FastAPI): http://localhost:<be-port>/docs
- Supabase Studio (DB GUI): http://127.0.0.1:54323

Apply the schema to a fresh local DB with:

```bash
supabase db reset   # replays supabase/migrations/*.sql
```

## Troubleshooting

- **Port already in use** (`EADDRINUSE`) — another build owns it. Do NOT
  stop that process (it is someone else's app) and do NOT guess another
  number: pick a free one with `flow app free-dev-port --bare` and start on
  that (`--port` for uvicorn, `npx next dev --port` for Next; update
  `BACKEND_URL` in `frontend/.env.local` if the backend port changed).
- **`supabase start` fails** — Docker isn't running. Start Docker Desktop and
  retry. The app itself still runs without it.
- **Supabase card shows "not configured"** — `NEXT_PUBLIC_SUPABASE_ANON_KEY`
  is empty in `frontend/.env.local`. Paste it from `supabase status` and
  restart `npm run dev` (NEXT_PUBLIC vars are inlined at build/dev start).
- **Drizzle can't connect** — `DATABASE_URL` points at 54322 which only exists
  while `supabase start` is up.
